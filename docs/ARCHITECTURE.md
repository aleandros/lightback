# Architecture

Five runtime packages, an optional build-time source package, an optional local MCP bridge, one playground, one browser test harness. Runtime dependency direction is `core ← widget ← react/vue/svelte`; `@lightback/source` is independent. Nothing in `core` touches the UI; nothing in `widget` knows about React.

## Data flow

```
page activity ──► collectors (ring buffers) ──┐
                                               │
user picks/drags ──► inspect/region ──► selections ─┤
                                               ├──► buildPayload(draft) ──► beforeSend ──► transport
user types note ─────────────────────────────┤        (redactDeep redaction)                 (JSON or multipart)
screenshot + crops (widget) ─────────────────┘
```

1. `createLightback(options)` installs collectors at browser app start, so the buffers are warm when the user eventually reports. On the server every installer is a no-op (including console and network); environment/page fields have empty defaults. DOM inspection and widget mounting throw explicit browser-DOM errors.
2. The widget keeps a **draft**: note text, selections, screenshot blob, crop blobs.
3. `client.send(draft)` builds the payload, runs `beforeSend`, and hands payload plus attachments to the transport.
4. The transport posts to `endpoint`, or calls the consumer's `send`.

### Session recovery

`persistence.ts` owns the version-1 IndexedDB `lightback-recovery` / `sessions` store. `sessionStorage["lightback:session:<key>"]` contains only a random record key; the default namespace is `default`. Core starts collectors immediately, then `client.ready` reads recovery data and merges the old events with new startup events in timestamp order, bounded by current ring limits and capture options. Context is always supplied fresh by the host. `RingBuffer` changes schedule a 100 ms checkpoint, and asynchronously completed network bodies notify it again. A generation captured before the database open and a serialized write queue ensure clear beats pending opens, reads and writes. Recovery sorts all retained timestamps before applying the current buffer limits, including when those limits shrink.

`recovery-redact.ts` scrubs every persisted metadata string and secret-named field, including embedded URL parameters and JSON bodies, before truncating. It omits inspection HTML and form-value fields. Selections are already sanitized for sensitive elements when described; draft `masks` are validated (reason and finite rect) on save and recovery. String values use `limits.string`; metadata field names have at least a 64-character budget so tiny value limits cannot rename recovery schema fields. Drafts keep at most 50 selections. Blob attachments are stored as binary ArrayBuffers and reconstructed on recovery to avoid native Blob write failures in WebKit environments. Encoded bytes are cached per Blob so page-hide checkpoints do not re-read backing files that navigation may revoke. They require `persistence.attachments: true`; the widget hands core only masked images. Default recovery stores metadata only. The default snapshot budget is 5 MiB. Oversized attachments and their references are omitted; oversized metadata deletes the checkpoint.

Records expire after the last checkpoint (default/maximum 30 minutes, configurable shorter). Reads purge expired, incompatible or malformed records. Expired records from closed tabs are physically removed on the next storage open; browser-restored/duplicated sessions can retain/copy the tab key. Denial, quota failure, blocked opens and missing storage fall back to memory; write errors invalidate the session key to prevent stale recovery. `persistence: false` makes no recovery storage calls. This database is independent of the demo inbox. The recovery schema is separate from payload version 1.

`getDraft`, `saveDraft`, `flushPersistence` and `clearPersistence` support custom editors. Successful sends clear the current stored draft and all four collector buffers, including intervening edits/events; failed/vetoed sends retain current state. The submitted payload is the snapshot built before the asynchronous hook/transport. Widget Discard calls the same clear API. Clear increments a per-client network epoch so pending fetch/XHR and cloned-body completions cannot refill buffers or schedule stale checkpoints. Destroy invalidates pending captures, flushes best-effort and unregisters listeners; it does not abort host requests. Independently created clients can be destroyed in any order without disabling or reviving each other’s collectors. The widget checkpoints each note input and selection/attachment change, guards late screenshot work after discard/destroy, and restores object URLs after recovery without resuming picking or send timers. The lazy shell reads only draft metadata to show the count, leaving the UI deferred. Older core clients without recovery APIs still mount with memory-only behavior.

### Selection shape

```ts
interface ElementSelection {
  id; kind: 'element' | 'region';
  selector; tag; elementId?; classes; text; attrs;
  rect; docRect;                 // viewport and document coordinates
  framework; components: string[]; chain: ComponentInfo[];
  source?: SourceLocation;       // file:line:col when a dev build exposes it
  props?: Record<string, unknown>;
  note?; html?;
  sensitive?: true;              // content withheld; selector and components remain
  crop?: string;                 // attachment name of the crop PNG
  region?: { rect; docRect; children: ElementSummary[] };
}
```

## `@lightback/widget`

A `<lightback-widget>` host with a Shadow DOM. It is created directly without registering a custom-element class, so repeated mounts do not collide in the registry. `index.ts` is the eager public entry; `ui.ts` holds the HTML template, the `Widget` class and all behaviour; `styles.ts` holds the CSS.

`WidgetOptions` accepts a partial `strings` table merged over `defaultStrings` (`strings.ts`), a forced light/dark or automatic theme via `data-theme`, and `hideTrigger`. Translation text is escaped wherever inserted into HTML. `triggerLabel` remains an alias; `strings.pillOpen` wins. The pill, panel, popover and pending surfaces expose matching CSS parts. Options are read at mount time.

### Lazy entry

`@lightback/widget/lazy` exports `mountLazyWidget()`. `lazy-controller.ts` mounts only a styled, translated pill using `shell.ts`, retains a stable host and coalesces pending open/pick intents. Options are snapshotted at mount. Closing cancels activation; destroying guards late resolution. Failures leave the trigger usable, call `onError`, and reject the action promise (with an internal rejection handler for void-style event callers). Core collectors remain active throughout the download.

The ESM build references a self-contained `lightback-ui.js` URL asset. Bundlers such as Vite emit it via `new URL(..., import.meta.url)`. Failed native imports are cached by browsers, so subsequent attempts use a fresh query parameter. Bundling UI dependencies into this asset avoids retaining failed dependency URLs. CommonJS uses a deferred `require` chunk and delegates network splitting to the consuming bundler. Source development uses the dev server's transformed `ui.ts`; production playground builds consume the built lazy package. `pnpm build:site` builds packages first so URL assets exist on a clean checkout.

The lazy standalone bootstrap (`lightback-lazy.iife.js`) includes core and the controller; it resolves `lightback-ui.js` beside its own script URL, with a `widgetUrl` override. The eager entry and IIFE remain available. Both paths reuse the UI class, styles and strings. Payload version stays 1.

### Pick mode

Capture-phase listeners on `document`: `pointermove` (highlight), `pointerdown`/`pointerup` (drag detection, 5px threshold; these call `stopPropagation` only), `click` (select or finish drag; suppressed after a drag; clicking the page while the popover is open saves the comment and continues), `dblclick`/`contextmenu`/`selectstart` (swallowed), window-capture `keydown` (keyboard traversal, selection, Tab containment and Escape). Anything inside an element with `data-lightback-ignore` is skipped.

`keyboard-picker.ts` traverses the light DOM with a TreeWalker, checking current visibility and ignoring hidden/inert/ARIA-hidden/ignored subtrees. Down/Up traverse document order; Right/Left traverse children/parents. Traversal stops at boundaries and revalidates targets before selection. A focused `data-ref="keyboardPicker"` application control owns arrow/Enter/Space handling; host elements never receive focus or synthetic activation. Keyboard navigation pauses while a capture runs to preserve its measured area. Targets scroll into view and share the pointer highlight, selection and mask paths. A translated polite live region announces locators only. Tab cycles through the pickbar and open popover controls. Comment Escape/Add more returns focus to the picker; picker Escape/Done opens review; Cancel returns to the panel or closes to the opener. The lazy shell's replaced trigger is resolved to its new equivalent for return focus. Close exits picking and removes its listeners. Widget key events do not bubble to host shortcut handlers. Region drawing remains pointer-only.

Entering pick mode with a `screenshot` capturer configured (and `autoScreenshot !== false`) queues a budgeted capture. Captures are serialized through `captureQueue` (each may hide and restore the host), and the budget is checked when a capture runs, against the area it captures: `captureCost` (`capture.ts`) counts what the capturer will clone (the same shared filter as `domCapturer`, rejecting boxless hidden subtrees in both modes and preserving fixed-element paths and off-screen layout boxes in viewport mode). Above `screenshotMaxElements` (default 8000) the capture is skipped and the base resolves to null with a toast and a highlighted Screenshot button. Automatic failure also highlights that button, until a screenshot is attached. Before sending an image-free draft with a configured capturer, the editor waits for capture, mask and crop jobs, then offers localized Add screenshot / Send anyway actions. Add captures manually and keeps editing; Send anyway persists for retries of this draft and resets on discard/success. Otherwise the capturer is called with `{ area }` (the whole document, or the viewport with `screenshotArea: 'viewport'`) inside `client.mute()`, and the bitmap is stored with that area (`Shot.area`). Capturers marked `OMITS_WIDGET` (`domCapturer`) leave the host out of the image, so the widget is not hidden and keeps focus and keystrokes. Other capturers get the host temporarily transparent (`opacity: 0`) with pointer events disabled; this omits its pixels while preserving comment focus, typed input and the live region. `visibility: hidden` would blur the editor and can scroll WebKit to the top. Original inline opacity and pointer-event styles are restored afterward. `domCapturer` is the shipped adapter for DOM-cloning renderers: for a viewport area it offsets the root with negative margins (a transform would carry fixed elements off the image) and filters out the children of any element entirely outside the area whose content cannot spill out of its box (`scrollWidth`/`scrollHeight` within its client size, non-zero box), keeping the element itself as a sized box so layout does not move. Ancestors of fixed elements are exempt. Box and no-client-rect checks are memoized per capture. A boxless `display: contents` wrapper is retained for its children; hidden subtrees and closed-details content are rejected before fixed-element discovery, cost counting or cloning. Boxless native select options (including hidden selected placeholders), SVG paint resources, column styling and word-break opportunities are retained because they can affect visible pixels and layout. Only boxless `display:none` roots and closed-details content are rejected; absent rectangles alone are insufficient. Budget and render filters share fixed-element discovery, while the renderer measures box geometry afresh when cloning begins; counting stops once the limit is exceeded. Copied preparation metadata never bypasses a custom capturer wrapper. Manual screenshot waits and button state belong to the current draft, so work from discarded drafts can remain serialized without blocking a new text-only send or changing a newer capture/send’s controls. Dropping off-screen elements outright is not an option: cloners inline computed heights, so a table that lost its rows stretches the rest. Sticky elements render unstuck (the clone is not scrolled). `screenshot.ts` decodes through `createImageBitmap` when available, otherwise through a temporary object URL and an image drawn to canvas; the URL is revoked on success or failure. Each new selection cuts a padded crop (`cropPadding`) from that bitmap, outlines the rect (dashed for regions) and stores it as `selection-N.png` with its document `area`. In viewport mode each selection records the viewport it was made on (`seenFrom`); when the base does not show the selection's part of that viewport (the page scrolled), the crop comes from `extraShot`, a budgeted capture of that viewport that later selections reuse while it covers theirs. Its sensitive rects join `baseMasks`. A new mask drops the reused capture (it lacks the mask), re-cuts every crop it overlaps whatever image it came from, and a crop job that finishes after a mask overlapping it was added discards its result for that re-cut. The crop is in bitmap pixels (capture scale, e.g. 2× on Retina); its card thumbnail is auto-sized with only maximum constraints, capped at the crop's CSS width, so it keeps its proportions and never grows past on-page size. Do not give it a fixed width or let the card's flex column stretch it. A restored crop's cap comes from its persisted `area`; drafts from before 0.2.2 have none, so it is estimated from the selection rect against the current page (`cropArea`). A restored screenshot with an `area` can be repainted by later masks. While a region is described, existing pins are made pointer-transparent so hit testing sees the page beneath them.

Every capture (automatic or manual) goes through `capture()`: sensitive rects are measured before and after the capturer, then `maskShot` (`screenshot.ts`) draws the decoded image to a canvas, fills each sensitive rect and reporter mask (2 CSS px bleed, scaled to the bitmap) and re-encodes. The raw bitmap is released and only the masked blob/canvas is kept, so previews, crops, recovery and sends never see unmasked pixels; failure drops the image and calls `onError`. In mask mode (`data-action="mask-mode"`), a click or drag adds a reporter mask instead of a selection. `addMask` queues a serial `maskJob` that repaints the base shot in place (bumping `baseVersion`, so in-flight crops of older pixels are discarded), re-masks a manual screenshot, drops then re-cuts this session's crops that overlap the area (plus in-flight crops the repaint discarded), and drops restored screenshots/crops whose geometry is unknown. A failed mask drops every image and bumps `baseVersion` so in-flight crops are discarded too. The hover tooltip uses `componentChain` (names only) rather than a full description. Masks are additive; Discard clears them. The draft records reporter masks (always, for later captures) and the sensitive rects painted into the attached screenshot and base as `masks`; core reports them in the payload only when attachments exist, with sensitive and reporter masks capped separately.

### Image annotations

`annotations.ts` owns independent vector layers for the screenshot and up to 50 crops (50 shapes per image, 20 undo snapshots for the open editor). `ui.ts` owns its translated template and dispatches `data-action` controls. Labeled icon buttons choose Select, Rectangle, Arrow, Ellipse or Text. Shift-drawing constrains ellipses to circles in bitmap pixels. Text marks carry up to 200 single-line characters; a focused text field updates the image and groups a typing session into one undo step. Text fields share a reserved slot with tool hints and are revealed after pointer gestures so layout changes cannot shift the drawing coordinates. The canvas uses explicit LTR/left text layout and a fixed language for identical attached-editor and detached-export rendering; empty text boxes have editor-only outlines and do not intercept strokes underneath. Pointer endpoints are normalized against the rendered canvas. Select hit-tests strokes in reverse drawing order before falling back to the smallest containing rectangle or ellipse, with CSS-pixel hit tolerance (larger for touch), and supports bounded movement and endpoint resizing. Tiny marks move as a whole instead of competing with overlapping handles. Remove is enabled only with a visible selection in Select mode. Temporary selection handles are painted only on the editor canvas, never on the exported PNG. Numeric percentage controls and the shape selector live in a collapsed native details section for keyboard creation and precise geometry editing; the focus trap excludes its hidden controls. The editor traps focus, makes other widget surfaces inert, and supports Escape. A single renderer paints orange/white rectangles, directional arrows, ellipses and fitted text at original bitmap dimensions. Existing crop outlines and opaque masks are source pixels. Shapes never propagate between images.

Widget screenshot/crop fields remain masked originals. The annotation cache supplies derived PNGs and URLs to previews and outgoing drafts. Encodes share a serial queue (including recovery), superseded work is skipped, and identity/job checks ignore completions after replacement/discard/destroy. Done awaits only the active image and allows closing on failure; send awaits all rendering and refuses failed images. Failures retain the editable draft. Automatic captures preserve the attached screenshot while it has marks or an open editor, and supply fresh pixels only to crops. Explicit Retake clears screenshot marks; mask repaint of that screenshot preserves them. Recut/dropped crops lose their independent layers.

`Draft.imageAnnotations` is optional, draft-only metadata keyed by attachment name. `saveDraft` receives masked originals plus normalized shapes; core validates numeric bounds/enums and caps layers/shapes independently of string redaction. Text content is redacted before its 200-character limit is applied; non-text marks cannot retain stray text metadata. Recovery persists no duplicate rendered bitmap, and prunes layers for attachments omitted by policy/budget. The widget reconstructs rendered images on restore. Payload v1 and transport attachment names stay unchanged: only flattened images are sent. Custom editors must flatten their own layers before sending.

### Send

`queueSend()` is used by the popover and Enter: leaves pick mode, hides panel and pill, shows the pending card, and fires `send()` after `sendDelay` ms (default 5000; 0 is immediate). `send()` awaits pending mask jobs, the base screenshot and all crop jobs, builds the draft (attachments: `screenshot.png`, `selection-N.png`), calls `client.send`, then resets and toasts on success or reopens the panel with the error. The panel's own Send button calls `send()` directly. Before starting transport, the widget checks that discard/destroy did not invalidate its pending image work. Late transport completions cannot invoke callbacks or reopen a discarded/destroyed widget; an already-started transport still follows the core send lifecycle.

## `@lightback/react`

`LightbackProvider({ client, widget, context })` mounts a lazy widget handle once, pushes `context` through `setContext` on change, and exposes `useLightback()` (the client) and `useLightbackWidget()` (the handle). Nothing else.

## `@lightback/source`

An independent Node build package; it adds no runtime dependency. `shared.ts` owns project-relative filtering and a Babel JSX visitor. `transformSource` parses original JSX/TSX with isolated Babel configuration and returns code plus a source map. The Vite adapter runs before JSX lowering with the resolved project root on both client and SSR builds. The Babel adapter traverses the original program before JSX visitors, supporting existing Babel pipelines such as Webpack's `babel-loader`. Both preserve explicit source attributes and stamp only native tags, after spreads. Core prefers stamped element locations over framework debug locations; component-chain metadata is unchanged. Payload version remains 1.

Default filters include JSX/TSX; dependencies, outside-root paths and virtual/query modules are always skipped. Vue/Svelte templates use their separate compiler adapters described below. Production fixtures build React 18 and React 19 JSX/TSX through Vite, compare minified client/SSR output, hydrate and inspect stamped elements. Packed checks cover ESM/CJS and all five source exports. See [the guide](guide/source-locations.md) for supported syntax and filtering.

### Vue and Svelte template stamping

`@lightback/source/vue` exports a Vite pre-plugin and `transformVueSource`; `@lightback/source/svelte` exports a compiler markup preprocessor and `transformSvelteSource`. Compiler AST offsets reference the complete original file. `template.ts` inserts escaped static attributes after parsed attributes and generates high-resolution maps; the common filter supplies project-relative filenames with extension-specific defaults. Vue respects native/component classification and a host-supplied custom-element predicate. Svelte visits regular elements across template blocks and snippets. External/Pug Vue templates and dynamic/raw markup remain outside automatic stamping. The respective compiler peers load only through their adapter entry. Runtime payload version remains 1; Svelte uses the existing explicit-attribute source fallback without a component-chain inspector.

## `@lightback/vue` and `@lightback/svelte`

Each integration exposes an initialization-time `provideLightback(client, options)` plus descendant helpers `useLightback()` and `useLightbackWidget()`. Vue uses an injection key, mount/unmount hooks and a readonly shallow widget ref. Svelte uses component context, `onMount` cleanup and a readable widget store. Widget configuration and client identity are captured once; reactive context is merged while mounted. SSR does not mount or subscribe. Cleanup disposes the lazy widget and watcher/subscription but never the caller's client. Svelte publishes ESM; Vue publishes matching ESM/CJS entries. See [framework integration](./guide/frameworks.md).

## `@lightback/mcp`

A separate Node 22+ package depends on core (prompt rendering and text redaction), the MCP SDK and Zod. No browser package depends on the server. Its `./browser` entry contains only the custom transport and optional plain-DOM thread surface, with type-only core imports; it does not import Node, Zod or the MCP SDK. Payload v1 is unchanged.

`cli.ts` provides `init`, `serve`, `browser-config`, `stop` and `stdio`. `config.ts` generates separate browser/agent tokens in a private, create-only JSON file, validates one exact frontend origin and a literal loopback URL, and refuses broadly readable files on POSIX. `stdio` creates missing configuration when given project/origin options and starts or reuses a detached `serve --managed` receiver. `lifecycle.ts` authenticates a health check and verifies package version and a digest of the complete connection config before reuse; a foreign listener is never killed or silently adopted. Concurrent launches converge on one create-only config file and one listening socket. Config publication uses atomic hard links, with exclusive writes and bounded reader retries on filesystems without link support. Managed receivers check the config on requests and once a second, closing when it is removed or changes. Open stdio connections keep it alive with periodic health checks. The receiver stays independent of coding-host process lifetime and exits after 30 minutes without authenticated activity (monotonic idle accounting, with a fresh window after sleep or a stalled timer); an authenticated agent-only shutdown route implements `stop`. Foreground `serve` remains available for diagnostics and has no idle shutdown. Each stdio connection proxies tools to that receiver, rereading its private config on every call. Stdout is reserved for MCP protocol in stdio mode.

`receiver.ts` binds 127.0.0.1, validates Host, exact Origin and browser token before reading bodies, and separates agent-only routes with bearer authentication and no browser Origins. It accepts existing JSON/multipart reports. Runtime schema checks guard prompt rendering while preserving compatible unknown payload fields; PNG files must match metadata exactly and satisfy byte/dimension limits. Read/upload/wait/concurrency bounds prevent unbounded queues. No submitted source path is opened or command executed.

`store.ts` owns bounded in-memory reports/images and separate conversation envelopes: project, session, report ID, status, revision, monotonic sequence and expiry. Payload IDs deduplicate identical retained submissions; conflicting content returns 409. Reads never acknowledge. Updates use expectedRevision and an idempotent messageId; reporter follow-ups reopen pending state. No exclusive lease or exactly-once editing guarantee is implied. Agent disconnects preserve reports; a receiver restart discards them and changes the instance ID, which invalidates old wait cursors. Fixed 30-minute retention applies to the entire thread from initial submission. There is deliberately no disk image persistence.

`mcp.ts` exposes five tools: list, bounded wait, prompt/paginated JSON retrieval, individual PNG image retrieval, and revision-checked status/reply. Tool/server descriptions identify captured data as untrusted and require workspace path validation. Host-initiated polling/waiting is the portable wake-up mechanism; server installation and notifications are not assumed to start agent turns. Models and file-edit permissions remain entirely in the coding host.

`browser.ts` connects custom send and follow-up redaction to the existing core client. Only fetch dispatch is muted, avoiding suppression of unrelated host activity while the receiver waits. The optional ignored Shadow DOM thread polls the scoped receiver, preserves unsent text on request failure, renders replies using textContent, and supports cleanup. It keeps sent thread state at the receiver; unsent follow-ups are not browser-persisted. The playground enables it only when a development `VITE_LIGHTBACK_BRIDGE` setting is supplied. The public demo's inbox is unchanged.

See [the coding-agent guide](guide/coding-agents.md) for exact limits, configuration, ownership and retry semantics. Node boundary/protocol tests run in `pnpm test`; `mcp-feedback.mjs` covers a browser-to-MCP-to-frontend-edit/review loop without inference. `scripts/check-mcp-hosts.mjs` separately checks installed client compatibility without paid model calls.

The public demo uses `vite build --mode demo` with base `/lightback/demo/` and hash navigation, so inbox links and refreshes work on a static host. `bootstrap.ts` activates a scoped service worker before mounting the app. `public/demo-worker.js` simulates only the demo API (including fetch and XHR); it does not cache assets or intercept the docs. The normal development API remains unchanged.

In demo mode, the custom `send` in `submissions.ts` stores payloads and attachment data URLs in IndexedDB, retaining the latest 20 reports. Reads and clears use the same store, with errors surfaced in the inbox/widget. Reports never leave the browser. This is example inbox storage, not SDK draft/buffer persistence. The external cross-origin noise button is omitted from the public demo.

Pages: Dashboard (stat cards with `data-testid`, invoice table, Export modal, ChaosPanel to generate console/errors/network/breadcrumb noise) and Inbox (Summary with sensitive flags and mask counts, Screenshot with selection overlays, Prompt, JSON). The sidebar account card is marked `data-lightback-sensitive` and the client configures `privacy.selectors: ['.chaos input']`, so demo screenshots show both kinds of mask.

## E2E (`e2e`)

Plain Node scripts on `playwright-core` against `pnpm dev`. System Chrome is the local default; `BROWSER=chromium|firefox|webkit` selects a Playwright engine and bypasses the Chrome channel/executable override. `lib.mjs` provides `launch(suite)` returning `page`, `assert`, `received()`, `reset()`, `finish()`, plus `W` (the shadow-root prefix) and `BASE_URL`. `run.mjs` runs all suites in sequence and exits non-zero on failure; it excludes the screenshot generator. The crop suite disables `createImageBitmap` to exercise the image/canvas fallback.

## Invariants worth protecting

- The payload is self-describing and bounded. Every list is ring-buffered and every string truncated by `limits.string`.
- Nothing produced by the widget or the capturer leaks into the report (ignore attribute + `mute`).
- Sensitive content never leaves inspection: no text, attributes, HTML or props from sensitive subtrees, and no image is kept before it is masked.
- Redaction is applied last and everywhere, so a new field cannot forget it.
- The widget has no dependency other than `core`, and `core` has none.

## Distribution and CI

Browser package module builds target ES2020; the optional MCP package targets Node 22 and modern local browsers, with separate `.d.ts` (ESM) and `.d.cts` (CommonJS) export conditions except the ESM-only Svelte integration. Packed checks keep strict type-resolution validation, accepting only the expected CJS-to-ESM diagnostic for that package and testing dynamic import from CJS. They exercise both current and minimum Vue/Svelte compiler peers. The widget adds `lightback.iife.js`, bundling core and exposing `window.Lightback = { createLightback, mountWidget, defaultStrings }`. Each tarball includes its own README and MIT license.

`.github/workflows/ci.yml` validates build, types, tests, packed consumers and strict Are the Types Wrong checks, plus a Chromium/Firefox/WebKit matrix. It is reusable so `release.yml` requires the same gates before running Changesets. Publishing uses npm 11 through pnpm, OIDC and provenance. The initial `0.1.0` packages were published locally on 2026-10-12. Existing published packages trust `aleandros/lightback` / `release.yml`; newly introduced package names need their initial npm setup and trusted publisher configured before automated publication. A new npm trusted publisher must complete its first successful workflow publish within two days of configuration ([npm requirements](https://docs.npmjs.com/trusted-publishers/)). Configure `aleandros/lightback`, workflow `release.yml`, with direct `npm publish` allowed. For a bootstrap patch, consume the patch changeset with `pnpm version-packages` and include the resulting version/changelog in the feature PR: with no pending changesets, merging to main publishes the unpublished version after CI, without a second version PR. MCP `0.2.0` was published manually; `0.2.1` is prepared for this first automated publish. Widget `0.1.1` verified the first actual OIDC upload with npm provenance on 2026-10-12 ([run](https://github.com/aleandros/lightback/actions/runs/38297673131)). Payload version stays 1.

## Documentation site

`docs` is a private VitePress workspace, with base `/lightback/`. `pnpm build:site` builds the docs and playground, then `scripts/assemble-site.mjs` copies the demo into the Pages artifact. `pnpm e2e:demo` serves those built files without a fallback or mock backend and exercises send, screenshots, inbox, refresh, isolation and clearing. CI runs it on all three browser engines. The home page and `docs/guide/` are public; internal planning files are excluded. `scripts/generate-reference.mjs` uses the TypeScript parser to regenerate payload and string reference tables during the docs build. CI builds the site and rejects stale generated tables. `.github/workflows/pages.yml` builds and deploys the site on main, with Pages configured to use Actions. The [site](https://aleandros.github.io/lightback/) is live. Build output and VitePress cache are ignored.
